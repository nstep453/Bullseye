## Overview

Bullseye gives investors a clear, jargon-free read on a single stock in seconds. Instead of a wall of financial data, it surfaces only the metrics that matter for how long you plan to hold, explains every number in plain English, and condenses the picture into one score with a short AI-written take.

It is a static, single-page web app with no build step and no backend.

### Design principles

- **One stock at a time.** No market dashboards or index tickers. The app loads no market data until a ticker is searched, which keeps API usage minimal.
- **Metrics matched to your time horizon.** A short-term trader and a retirement saver care about different numbers.
- **Every metric explains itself.** Each figure has an ⓘ tooltip, and a searchable glossary is always one click away.
- **Fast and lightweight.** One HTML file, vanilla JavaScript, installable as a PWA.

## Features

| Feature | Description |
| --- | --- |
| **Bullseye Score** | A 0 to 100 rule-based score with a verdict ("Bullseye!", "On target", "Close, but not quite", "Off target", "Missed") and a short summary of the stock's strongest and weakest areas. |
| **Why this score?** | An expandable breakdown showing which metrics help, are neutral, or hurt the score. |
| **AI vibe check** | A three-word "vibe" and a one- or two-sentence take, generated by an open-weight language model through Groq's free tier. Falls back to a rule-based label if the AI is unavailable. |
| **Time-horizon modes** | Short, Medium and Long term views, each with a tailored set of metrics. |
| **Custom metrics** | Build your own view from 80 available metrics, grouped by category and searchable. Preferences are stored in the browser. |
| **Custom formulas** | Create your own named metrics by combining any other metrics with arithmetic, for example operating income divided by total debt. Custom metrics are display-only and saved in the browser. |
| **Price chart** | Interactive price history (1M, 3M, 1Y, 5Y) that opens on a range matched to the selected horizon. Hover or touch to read the price on any date. |
| **Earnings heads-up** | On the Short term view, a notice appears when a company reports earnings within the next five business days, with the date, analyst estimates and recent beat/miss history. |
| **Analyst consensus** | A visual breakdown of strong buy, buy, hold, sell and strong sell ratings. |
| **Latest headlines** | Recent company news linked to the original source. |
| **Ticker autocomplete** | Search by company name or ticker and pick from suggestions. |
| **Shareable links** | Every result has a URL such as `?s=AAPL&h=short` that opens that stock and horizon directly. |
| **Learn mode** | A skippable first-visit tour and a searchable glossary with an Essential tab for beginners and an All tab covering every metric and term. |
| **Light and dark themes** | Follows the system preference and can be toggled manually. |
| **Installable (PWA)** | Add to a phone or desktop home screen for a full-screen, app-like experience. |

## Time horizons

| Horizon | Focus | Metrics |
| --- | --- | --- |
| **Short term** (days to weeks) | Momentum, volatility, trading activity | 5-day return, 3-month return, position in 52-week range, beta, average daily volume, P/E ratio |
| **Medium term** (months to a couple of years) | Growth, valuation, trend | 6-month return, revenue growth (1yr), EPS growth (1yr), P/E ratio, operating margin, position in 52-week range, current ratio |
| **Long term** (years) | Quality, profitability, balance sheet, income | Revenue growth (5yr), EPS growth (5yr), net profit margin, return on equity, debt/equity, price/sales, dividend yield, market cap |
| **My metrics** | User-defined | Any of the 80 available metrics |

## How the Bullseye Score works

The score is deterministic and transparent:

1. Each scoreable metric in the current view is mapped to a value between 0 and 1 using a fixed benchmark range. For example, a P/E near 12 rates well and one near 40 rates poorly, while 1-year revenue growth is scaled from -5% to +25%.
2. Analyst consensus is included as an additional input, weighted at 1.5 times a standard metric.
3. The inputs are averaged and scaled to 0 to 100.

| Score | Verdict |
| --- | --- |
| 75 to 100 | Bullseye! |
| 60 to 74 | On target |
| 45 to 59 | Close, but not quite |
| 30 to 44 | Off target |
| 0 to 29 | Missed |

Informational metrics (market cap, average volume, dividend yield, EPS) are displayed but have little or no effect on the score. Because the score only uses the metrics in view, it changes with the selected horizon. The earnings notice and AI vibe check are informational and do not affect the score.

> **Note:** Benchmarks are general rules of thumb and are not adjusted for sector. A P/E that looks high for a utility may be normal for a software company.

## Getting started

Bullseye is a static site, so there is nothing to install.

### Run locally

```bash
git clone https://github.com/nstep453/Bullseye.git
cd Bullseye
```

Open `index.html` in a browser. To test the service worker and install prompt, serve the folder over HTTP instead:

```bash
python3 -m http.server 8000
# then visit http://localhost:8000
```

### Configuration

API keys are defined near the top of the script in `index.html`:

```js
const KEYS  = ['FINNHUB_KEY_1', 'FINNHUB_KEY_2'];  // market data
const GROQ  = ['GROQ_KEY_1'];                      // AI vibe check
const TD    = ['TWELVE_DATA_KEY_1'];               // price chart
const PROXY = '';                                  // optional proxy URL
```

Each list accepts multiple keys. Requests are rotated across them, and any key that returns a rate-limit error is skipped for 60 seconds, which raises effective throughput on free plans.

Free keys are available from [Finnhub](https://finnhub.io), [Twelve Data](https://twelvedata.com) and [Groq](https://console.groq.com).

### Deploy to GitHub Pages

1. Push the project files to the `main` branch of a public repository.
2. Open **Settings → Pages**.
3. Under **Build and deployment**, set **Source** to **Deploy from a branch**, then select **main** and **/ (root)**.
4. Save. The site is published at `https://YOUR_USERNAME.github.io/YOUR_REPO/` within a few minutes.

## API usage and rate limits

A fresh stock lookup issues five requests to Finnhub:

| Endpoint | Purpose |
| --- | --- |
| `/quote` | Current price and daily change |
| `/stock/profile2` | Company name, logo, exchange and industry |
| `/stock/metric` | Fundamentals, returns, margins and ratios |
| `/stock/recommendation` | Analyst consensus |
| `/company-news` | Headlines from the past seven days |

Additional requests are made only when needed:

- **Price chart:** one Twelve Data `time_series` request per stock. The full five-year daily history is fetched once and sliced client-side into each range.
- **AI vibe check:** one Groq chat completion per stock, per horizon, per day. Results are cached in the browser.
- **Balance-sheet metrics (My metrics only):** when a selected metric needs filing data (cash, debt, assets and similar), two `/stock/financials-reported` requests (annual and quarterly) are made for that stock. Values are extracted from the latest SEC filing on a best-effort basis and show N/A when a company's filing doesn't map cleanly.
- **Earnings notice (Short term view):** one `/calendar/earnings` request, plus `/stock/earnings` only when a report is due within five business days.
- **Autocomplete:** one `/search` request per debounced pause in typing.

Free-tier limits are per key and change over time, so check each provider's current terms. Results are cached in memory for the session, so revisiting a stock or switching horizons costs little or nothing.

## Progressive web app

Bullseye ships with a web app manifest, icons and a service worker. When served over HTTPS (as on GitHub Pages), browsers offer an install option, and the app shell loads from cache when offline. Market data, prices and AI responses always come from the network and are never cached by the service worker.

## Securing API keys

Because Bullseye runs entirely in the browser, any key placed in `index.html` is visible to anyone who views the page source. This is acceptable for low-risk free-tier keys but is not recommended for sensitive or paid keys. Keys that have been committed to a public repository should be considered exposed and rotated if abused.

For a hardened deployment, `worker.js` is a reference [Cloudflare Worker](https://workers.cloudflare.com) that holds the Finnhub and Groq keys server-side, caches responses, and only answers requests from an allowed origin:

1. Create a Worker and deploy the contents of `worker.js`.
2. Add the secrets `FINNHUB_KEYS` and `GROQ_KEYS` (comma-separated) and the variable `ALLOWED` (your site's origin, for example `https://YOUR_USERNAME.github.io`).
3. Set `PROXY` in `index.html` to the Worker URL and empty the `KEYS` and `GROQ` lists.

The Worker proxies Finnhub and Groq requests. Twelve Data requests are made directly from the browser.

## Limitations

- Covers US-listed stocks available on the free tiers of the data providers.
- Some metrics may show N/A for smaller or newer companies.
- Data may be delayed and is provided as-is by third parties.
- Earnings dates and estimates can change.
- The price chart depends on a free plan with a daily request cap and can be temporarily unavailable on busy days.
- AI-generated text can be inaccurate. It is given the app's computed metrics but may still misstate them.
- The score is a simplified, rule-based estimate and not a prediction.
